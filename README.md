# جسور — النشر الذكي (Jusoor AutoPost)

منصة SaaS متعددة الشركات لأتمتة التسويق بالمحتوى: تسحب الأخبار والمحتوى من مصادرك وموقعك ومتجرك، وتكتب بالذكاء الاصطناعي منشورات كاروسيل بهوية كل شركة، وتمرّرها على مراجعة بشرية قبل نشرها على فيسبوك وإنستغرام والمنصات الأخرى — مع قسم كامل **للنشرات البريدية** (تصميم، قوائم مشتركين، جدولة، وإحصاءات فتح ونقر).

**الإصدار الحالي:** `4.7.1` — للتحقق افتح `https://<رابط-الخادم>/api/health` وانظر إلى `version`.

## ماذا يفعل؟

```
المصادر (موقعنا الإلكتروني / مواقع / RSS / متجر)
      │  سحب تلقائي حسب الجدول
      ▼
مقالات ومنتجات جديدة ──► فلترة (مكرر / قديم / قصير / بعيد عن المجال)
      │
      ▼
الذكاء الاصطناعي (Gemini / Mistral / Groq / Cloudflare / OpenRouter…)
      │   محرّك واحد مع بديل تلقائي، أو عدة محرّكات بالتوازي مع حَكَم يختار الأفضل
      ▼
تصميم الشرائح 1080×1350 بهوية الشركة (أكثر من 20 قالبًا لكل مجال)
      │
      ▼
فحص الجودة ──► قائمة المراجعة ──► تعديل / اعتماد / رفض
      │
      ├──► نشر فوري أو مجدول ──► Buffer | Meta | upload-post
      └──► نشرة بريدية ──► Brevo | Resend | SMTP ──► إحصاءات الفتح والنقر
```

## الأقسام

| القسم | الوظيفة |
|---|---|
| **قائمة المراجعة** | المسودات مجمّعة حسب اليوم، مع تبويبات للحالات وبحث وتحديد جماعي |
| **محرر المنشور** | معاينة الشرائح، وتعديل كل نص وإعادة توليده، وتغيير قالب البطاقة، ورفع خلفية، وفحص الجودة، والنشر أو الجدولة، وتنزيل الصور والنص |
| **المصادر** | أنواع مصادر تناسب كل مجال، ومصدر **موقعنا الإلكتروني** في كل المجالات، مع اختبار المصدر قبل حفظه |
| **المنتجات والخدمات** | استيراد المنتجات أو الخدمات أو الدورات من موقع الشركة (Shopify وWooCommerce وأي موقع)، ومنشور لكل منتج مع رابطه |
| **النشرات البريدية** | 12 نوعًا من النشرات، وتصاميم لكل مجال، وقوائم مشتركين، وجدولة، وإحصاءات |
| **التقويم** | تخطيط المواضيع حسب الأيام، وتوليد منشور من أي موضوع |
| **الحملات** | تجميع المنشورات تحت هدف تسويقي مع إحصاءات لكل حملة |
| **الهوية البصرية** | الشعارات والألوان والخطوط والقوالب وقنوات النشر، مع معاينة حيّة |
| **المكتبة** | صور الشركة ووسائطها لاستخدامها في المنشورات |
| **الفريق** | دعوة أعضاء بأدوار: مالك، محرر، مراجع |
| **الإحصاءات** | المقالات المسحوبة، والمنشورات حسب الحالة والمصدر، ونتائج النشر لكل منصة |
| **الإعدادات** | اللغة واللهجة والنبرة والجمهور، والجدولة، والنشر، والمفاتيح والاتصالات |
| **لوحة المشرف العام** | إدارة الشركات المشتركة وتفعيلها أو إيقافها، والتنقل بينها |

## تعدد الشركات (SaaS)

- كل شركة تسجّل حسابها بنفسها (يمكن إيقاف ذلك بـ `ALLOW_SIGNUP=false`)، وبياناتها معزولة تمامًا عن غيرها على مستوى قاعدة البيانات.
- **المشرف العام** (`ADMIN_EMAIL`) يرى كل الشركات ويتنقل بينها من القائمة في الشريط الجانبي.
- **الأدوار داخل الشركة:**
  - **مالك:** كل الصلاحيات، بما فيها المفاتيح وحساب البريد.
  - **محرر:** إنشاء المحتوى وتعديله ونشره.
  - **مراجع:** القراءة والاعتماد أو الرفض فقط.

### المجالات

السفر والسياحة، الأخبار والإعلام، التقنية، المطاعم والكافيهات، التعليم، المتاجر الإلكترونية، العقارات، الموضة، الصحة والعيادات، التجميل، السيارات، الفعاليات والمؤتمرات، **التدريب والتأهيل**، **المنظمات غير الربحية**، ومجال عام.

لكل مجال: نبرة كتابة خاصة، وأنواع مصادر مناسبة، وأمثلة وتلميحات في كل الحقول، وقوالب بطاقات وتصاميم نشرات تناسبه.

### اللغات واللهجات

- **واجهة المنصة ورسائل الخادم:** العربية، الإنجليزية، الماليزية، الفرنسية.
- **لغة المحتوى:** نفس اللغات الأربع.
- **اللهجات العربية:** الفصحى، الفصحى المبسطة، الخليجية، المصرية، المغربية.

## بطاقات المنشورات والهوية

- **أكثر من 20 قالب بطاقة لكل مجال** (32 قالبًا إجمالًا)، والصورة هي المحتوى الأساسي دون مساحات تغطيها. يختار المستخدم القوالب التي تعمل، أو يترك النظام يتنقل بينها كلها.
- **عدة شعارات** (ملوّن، أبيض، داكن) مع شعار رئيسي. النظام يختار تلقائيًا النسخة المناسبة لخلفية كل شريحة، ولا يظهر في البطاقة إلا شعار واحد.
- **الألوان:** أسماء أدوار قياسية (رئيسي، ثانوي، تمييز، سطح، نصوص…)، وزر **العودة للهوية الافتراضية** المستخرجة من الشعار الملوّن.
- **ألوان تلقائية من الصورة** (اختياري): تُبنى ألوان البطاقة من صورة الغلاف مع ضمان تباين مقروء.
- **الخطوط:** Cairo إلى جانب خطوط عربية (Tajawal، Almarai، IBM Plex Sans Arabic، Noto Kufi Arabic، Readex Pro، El Messiri) ولاتينية (Poppins، Montserrat، Playfair Display، DM Sans، Raleway، Inter). الخطوط مضمّنة داخل الخادم ولا تعتمد على الإنترنت.

## النشرات البريدية

- **12 نوعًا يختار منها المستخدم:** التنسيقية، التعليمية، الإخبارية، المقالات والمدونات، السرد القصصي، التحليلية، الترويجية، التحديثات المؤسسية، الداخلية للموظفين، التفاعلية والاستطلاعية، المناسبات والفعاليات، الهجينة (70/30).
  - كل نوع يوجّه أسلوب الكتابة والتصميم المقترح وعدد الأقسام. **النوع داخلي فقط ولا يظهر للمستلم.**
  - نشرة الفعاليات تعرض صندوق الموعد والمكان والتسجيل، ونشرة الاستطلاع تضيف تصويتًا بنقرة واحدة مع نتائجه.
- **المحتوى:** من موضوع تكتبه، أو من منشوراتك المعتمدة، أو منتجاتك، أو مقالات المصادر.
- **التصميم:** 6 تخطيطات بريدية (كلاسيكي، مجلة، بسيط، جريء، ملخص، إبراز)، 4 إلى 6 منها لكل مجال، بهوية الشركة.
- **اللغة والخط:** تختار لغة النشرة وخطها عند الإنشاء أو من المحرر. تغيير اللغة يترجم النشرة كاملة تلقائيًا مع الحفاظ على التصميم والروابط. الخطوط تظهر في Apple Mail وiPhone وOutlook للماك، وGmail يعرض خطًا آمنًا مشابهًا.
- **المشتركون:** استيراد من Excel أو CSV أو TXT أو vCard، أو لصق نص، أو إضافة يدوية، مع قوائم متعددة وتصدير CSV.
- **الإرسال:** فوري أو مجدول، مع رسالة تجريبية، ورابط إلغاء اشتراك بنقرة واحدة (ترويسة `List-Unsubscribe`).
- **الإحصاءات:** عدد المستلمين، ومن فتح ومتى، ومن نقر، وإلغاءات الاشتراك، ونتائج الاستطلاع.
- **حساب الإرسال** (من **النشرات ← الإعدادات**، للمالك فقط):

| المزوّد | ملاحظة |
|---|---|
| **Brevo** (موصى به) | مفتاح API، ويعمل على Railway |
| **Resend** | مفتاح API، ويعمل على Railway |
| **SMTP** | بريد الشركة (Gmail، Outlook، Zoho…) مع إعدادات جاهزة. Railway يحجب منافذ SMTP غالبًا، لذلك يُفضّل Brevo أو Resend |

## التشغيل على جهازك

المتطلبات: Python 3.11 أو أحدث، وNode 20 أو أحدث.

```bash
# 1) الخادم
cd backend
python -m venv .venv && source .venv/bin/activate   # على Windows: .venv\Scripts\activate
pip install -r requirements.txt
playwright install chromium
cp .env.development.example .env        # ثم ضع مفتاح ذكاء اصطناعي واحدًا على الأقل
python -m scripts.seed_demo              # اختياري: بيانات تجريبية
uvicorn app.main:app --reload --port 8000

# 2) الواجهة (في نافذة أخرى)
cd frontend
npm install
npm run dev                              # http://localhost:5173
```

- **بدون مفتاح ذكاء اصطناعي** يعمل النظام بنصوص تجريبية.
- **على جهازك** يعمل كل شيء ما عدا النشر الفعلي، لأن Meta وBuffer يحتاجان روابط صور عامة.
- **توثيق الـ API** على `http://localhost:8000/api/docs` (يُغلق تلقائيًا في الإنتاج).

## النشر على الإنترنت

خدمتان فقط: **Railway** للخادم وقاعدة البيانات والصور، و**Vercel** للوحة.

### 1) الخادم على Railway

1. **New Project → Deploy from GitHub repo**، واضبط **Root Directory** على `backend`.
2. **Settings → Volumes → Add Volume** ومسار التركيب `/app/data`. بدونه تضيع البيانات مع كل تحديث.
3. **Variables:**

| المتغير | القيمة |
|---|---|
| `ENVIRONMENT` | `production` |
| `DATABASE_URL` | `sqlite:////app/data/autopost.db` |
| `MEDIA_DIR` | `/app/data/media` |
| `STORAGE_BACKEND` | `local` |
| `PUBLIC_BASE_URL` | رابط الخادم على Railway (ضروري لروابط الصور وتتبع البريد) |
| `CORS_ORIGINS` | رابط اللوحة على Vercel |
| `ADMIN_EMAIL` | بريد المشرف العام |
| `ADMIN_PASSWORD` | كلمة مرور قوية |
| `SECRET_KEY` | نص عشوائي طويل |
| `ALLOW_SIGNUP` | `true` لتسمح للشركات بالتسجيل، أو `false` |
| مفاتيح الذكاء الاصطناعي | اختيارية هنا، والأسهل إضافتها من اللوحة |

4. **Settings → Networking → Generate Domain** للحصول على الرابط العام.

عدد النسخ يبقى **1**، لأن المجدول (السحب والنشر وإرسال النشرات المجدولة) يعمل داخل الخادم.

> عند كبر البيانات: أضف **Postgres** إلى مشروع Railway واجعل `DATABASE_URL = ${{Postgres.DATABASE_URL}}`.

### 2) اللوحة على Vercel

1. **Add New → Project** من نفس المستودع، و**Root Directory** = `frontend`.
2. متغيّر واحد: `VITE_API_URL` = رابط الخادم على Railway.
3. **لا تضف** `VITE_SUPABASE_URL` ولا `VITE_SUPABASE_ANON_KEY` إلا إن أردت وضع Supabase.

### 3) التحديث من GitHub

- ارفع الملفات داخل المجلدين `backend` و`frontend` نفسيهما، وليس في مجلدات جديدة مثل `backend 2`.
- GitHub يقبل حتى 100 ملف في الرفع الواحد.
- بعد الرفع: Vercel ينشر تلقائيًا، وفي Railway اضغط **Deploy** إن لم يبدأ تلقائيًا، ثم تحقق من `version` في `/api/health`.

### البديل: Supabase

شغّل `supabase/schema.sql`، واضبط `SUPABASE_URL` و`SUPABASE_ANON_KEY` و`SUPABASE_SERVICE_ROLE_KEY` و`ALLOWED_EMAILS` و`STORAGE_BACKEND=supabase`، واترك `ADMIN_EMAIL` و`ADMIN_PASSWORD` فارغين، وأضف `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY` في Vercel.

## المفاتيح من داخل اللوحة

كل المفاتيح تُضاف من **الإعدادات ← المفاتيح والاتصالات** بلا حاجة للرجوع إلى الاستضافة:

- محرّكات الذكاء الاصطناعي مع اسم النموذج ووضع العمل (محرّك واحد أو بالتوازي)
- Pexels وPixabay للصور المجانية
- Buffer وMeta وupload-post للنشر
- حساب البريد للنشرات (من قسم النشرات)

المفاتيح تُحفظ في قاعدة بياناتك ولا تعود إلى المتصفح بعد الحفظ؛ تظهر فقط حالتها وآخر أربعة أحرف. متغيرات البيئة تبقى قيمة افتراضية، وما يُكتب في اللوحة يتجاوزها.

## محرّكات الذكاء الاصطناعي

- **محرّك واحد:** يكتب المحرّك الأساسي، وإن فشل يتولّى المحرّك الجاهز التالي تلقائيًا.
- **عدة محرّكات بالتوازي:** كلها تكتب في الوقت نفسه، ثم يقارن **الحَكَم** بين النسخ ويختار الأفضل مع السبب. إن تعطّل محرّك يكمل الباقون.
- زر **اختبار الاتصال** يجرّب كل المحرّكات الجاهزة دفعة واحدة.

| المحرّك | المفتاح من |
|---|---|
| Gemini | aistudio.google.com |
| Mistral | console.mistral.ai |
| Groq | console.groq.com/keys |
| Cloudflare Workers AI | لوحة Cloudflare (مفتاح + Account ID) |
| OpenRouter | openrouter.ai/keys (نماذج مجانية بحد يومي) |

## ربط منصات النشر

### Buffer (الأسهل)

1. أنشئ **API key** من إعدادات Buffer وأضفه من اللوحة.
2. من **الهوية البصرية ← قنوات النشر ← تحميل القنوات** اختر الصفحة والحسابات.
3. من **الإعدادات** اختر النشر الفوري أو الإضافة لطابور Buffer.

### Meta Graph API (مجاني)

1. أنشئ تطبيقًا من نوع **Business** في developers.facebook.com، وأضف **Facebook Login for Business** و**Instagram**.
2. الصلاحيات: `pages_show_list`، `pages_read_engagement`، `pages_manage_posts`، `instagram_basic`، `instagram_content_publish`، `business_management`.
3. أنشئ رمزًا دائمًا من **Business Settings → System users**، وأضفه من اللوحة.
4. في **الهوية البصرية** أدخل **Facebook Page ID** و**Instagram User ID**.
5. حدود إنستغرام: 100 منشور يوميًا، و10 شرائح كحد أقصى، وJPEG فقط (النظام يلتزم بذلك تلقائيًا).

### upload-post.com

أنشئ **API key**، واربط حساباتك تحت **Profile**، ثم أدخل اسم المستخدم وFacebook Page ID في **الهوية البصرية**. يدعم أيضًا لينكدإن وتيك توك وX وثريدز وبينتريست.

## المصادر والمنتجات

- **موقعنا الإلكتروني:** متاح في كل المجالات؛ محتواه لا يُرفض لبعده عن المجال ولا يُضاف إليه ذكر مصدر.
- **RSS:** ضع رابط الخلاصة فقط.
- **موقع:** ضع رابط صفحة القسم، ويكتشف النظام روابط المقالات. للدقة أضف **نمط الروابط** أو **محدد CSS**.
- **اختبر قبل الحفظ:** زر **اختبار** يعرض الروابط والمقالات المكتشفة.
- **المنتجات:** من **المنتجات والخدمات ← مزامنة**؛ يجرّب Shopify ثم WooCommerce ثم خريطة الموقع وبيانات الصفحات، ثم أنشئ منشورًا لكل منتج أو لعدة منتجات دفعة واحدة.

## عند وجود مشكلة

افتح `https://<رابط-الخادم>/api/health`. الصفحة تعرض الإصدار وحالة كل إعداد، وتسمّي الخطأ في قائمة `problems` دون كشف أي مفتاح.

| ما تراه | المعنى |
|---|---|
| `"version"` قديم بعد الرفع | الملفات لم تصل إلى مجلد `backend` الصحيح، أو لم يُعد النشر في Railway |
| `"mode": "internal"` | الدخول بالبريد وكلمة المرور مفعّل |
| `"mode": "unconfigured"` | لا `ADMIN_EMAIL`/`ADMIN_PASSWORD` ولا إعداد Supabase |
| `"environment": "development"` | أضف `ENVIRONMENT=production` عند الإطلاق للعملاء |
| `"public": false` في storage | الصور غير متاحة للعامة، والنشر سيفشل |

## الأمان

- **العزل:** بيانات كل شركة معزولة على مستوى الاستعلامات نفسها.
- **الدخول:** جلسات موقّعة، وتغيير `ADMIN_PASSWORD` يلغي كل الجلسات القديمة.
- **الأدوار:** المفاتيح وحساب البريد للمالك فقط.
- **المفاتيح:** على الخادم فقط، ولا يصل أي مفتاح إلى المتصفح.
- **الملفات المرفوعة:** يُتحقق من نوعها وحجمها (الصور حتى 10 ميغابايت، والشعار حتى 3 ميغابايت).
- **التوثيق** `/api/docs` يُغلق تلقائيًا عند `ENVIRONMENT=production`، والواجهة لا تفهرسها محركات البحث.

## ملاحظة عن حقوق المحتوى

النظام يعيد صياغة المقالات ولا يترجمها حرفيًا، ويذكر المصدر افتراضيًا. مع ذلك راجع شروط كل موقع، وفضّل صور مكتبتك أو Pexels/Pixabay، ولا تنشر دون مراجعة خاصة ما فيه أرقام أو أسعار.
